# 研究检查表与术语表

## 1. 让 AI 写代码前

先填写下面十项。答不出来时，暂时不要写复杂代码。

- [ ] **研究问题**：一句话说明想验证什么。
- [ ] **经济逻辑**：说明谁承担风险、谁可能反应较慢，或什么限制让机会可能存在。
- [ ] **资产范围**：明确研究哪些股票、ETF、期货或其他资产。
- [ ] **时间范围**：明确开始、结束日期以及数据频率。
- [ ] **可用信息时间**：每个字段在历史上何时真正公开。
- [ ] **交易规则**：什么时候产生信号，什么时候允许成交。
- [ ] **仓位规则**：每次买多少，最大持有多少。
- [ ] **成本规则**：手续费、价差、滑点、市场冲击、融资和做空成本。
- [ ] **数据分割**：样本内、验证集、最终测试集的边界。
- [ ] **失败条件**：出现什么结果时承认假设不成立。

## 2. AI 交付代码后

- [ ] 程序明确记录数据来源、下载时间和字段说明。
- [ ] 日期顺序、重复、缺失、异常价格和时区已经检查。
- [ ] 至少一笔交易由人手算，与程序完全一致。
- [ ] 当天收盘后得到的信号，没有按当天更早的价格成交。
- [ ] 财务指标按真实披露时间使用，没有提前使用季度答案。
- [ ] 股票池包含当时已退市和失败的公司，或明确承认数据不包含它们。
- [ ] 复权、分红、拆股、合约换月和汇率处理有说明。
- [ ] 参数只在样本内和验证集选择，最终测试集没有反复查看。
- [ ] 与简单基线比较，而不只展示策略自身曲线。
- [ ] 加入至少三档交易成本，并报告换手率。
- [ ] 展示一片相邻参数，不只展示最佳点。
- [ ] 检查不同市场阶段、不同资产和极端时期。
- [ ] 报告收益同时报告波动、最大回撤和最差时期。
- [ ] 保存随机种子、软件版本和运行配置。
- [ ] 自动测试通过，但仍完成了人工逻辑检查。

## 3. 论文阅读卡

每篇论文只填写一张卡，不需要一开始逐公式推导。

```text
论文标题：
研究问题：作者想知道什么？
数据：研究了哪些对象、哪些年份？
方法：怎样把问题变成可计算的检验？
主要结果：作者发现了什么？
可能机制：为什么会出现这个结果？
成本与限制：论文忽略或简化了什么？
最可能的偏差：未来信息、幸存者、多重检验还是其他？
我能复现的最小部分：
什么证据会推翻它：
```

第一次阅读只看标题、摘要、图表、结论和数据段。第二次阅读再看方法。第三次才处理公式和复现。**摘要**是论文开头对问题、方法和结论的简短概括。

## 4. 策略验收卡

```text
策略名称：
一句话规则：
收益可能来自：风险补偿 / 行为偏差 / 市场限制 / 暂不清楚
需要的数据：
每次决策当时可见的信息：
预期持有时间：
最大仓位和杠杆：
所有成本：
基准：
样本外结果：
最差历史阶段：
相邻参数结果：
容量限制：
停止条件：
仍未解决的问题：
```

**行为偏差**是人类决策中反复出现的非理性倾向，例如对新信息反应过慢或过度反应。**市场限制**是阻止交易者立即消除机会的现实障碍，例如不能方便做空、资金有限或交易成本太高。

## 5. 核心术语表

### 市场与策略

| 术语 | 通俗解释 |
|---|---|
| Alpha | 不能被选定基准或常见风险因子解释的超额表现。它不是“绝对赚钱”，估计也可能只是噪声 |
| Beta | 资产或策略对某个市场或因子变化的敏感程度 |
| 风险溢价 | 因为承担某类不受欢迎的风险，投资者可能要求的额外预期收益 |
| 基准 | 用于比较的参照，例如市场指数、现金收益或简单买入持有 |
| 多头 | 买入后期待价格上涨的仓位 |
| 空头 | 先借入卖出、期待以后低价买回的仓位 |
| 对冲 | 建立方向相反的仓位，减少某类风险；通常不能消除所有风险 |
| 套利 | 严格含义是几乎无风险地锁定收益；现实中的“统计套利”仍会亏损 |
| 流动性 | 能否快速完成交易，同时不明显推动价格 |
| 容量 | 策略在市场冲击明显破坏收益前，大约能容纳多少资金 |
| 换手率 | 一段时间内买卖金额相对于组合规模的比例 |
| 融资成本 | 借入资金建立或维持仓位所支付的利息和费用 |
| 融券成本 | 借入证券用于做空时支付的费用，并可能遇到无法继续借到的风险 |

### 数据与统计

| 术语 | 通俗解释 |
|---|---|
| 观测值 | 数据表中的一个实际记录，例如某只股票某天的收益 |
| 样本 | 实际拿到并用于研究的一部分对象或时期 |
| 总体 | 真正希望得出结论的全部对象或未来情况 |
| 噪声 | 没有稳定预测意义的随机变化 |
| 信号 | 模型认为与未来结果有关的信息，或由规则产生的买卖指示 |
| 特征 | 输入模型的可计算信息 |
| 标签 | 希望模型学习预测的答案 |
| 参数 | 由研究者设定或由模型从数据估计的数字 |
| 估计 | 使用有限样本猜测未知真实数值的过程 |
| 置信区间 | 表达估计不确定性的数值范围 |
| p 值 | 假设没有真实效果时，看到当前或更极端结果的概率；不是策略有效概率 |
| 相关 | 两个变量倾向共同变化，但不自动表示因果关系 |
| 因果 | 一个因素的改变确实导致另一个结果改变 |
| 平稳性 | 时间序列的主要统计规律不会任意随时间改变 |
| 协整 | 多个会漂移的序列之间存在长期相对稳定的线性关系 |
| 异常值 | 明显远离大多数数据的记录，可能是真实极端事件，也可能是数据错误 |
| 肥尾 | 极端结果比正态分布预计得更常见 |

### 回测与验证

| 术语 | 通俗解释 |
|---|---|
| 回测 | 用历史数据模拟策略当时会怎样交易 |
| 样本内 | 用来提出规则和调整参数的数据 |
| 验证集 | 用来比较方案、选择参数的数据 |
| 测试集 | 全部规则冻结后只做最终评价的数据 |
| 样本外 | 没有参与规则选择的数据或未来时期 |
| 前视偏差 | 历史决策用了当时尚不知道的未来信息 |
| 数据泄漏 | 测试答案或未来信息进入训练和决策过程 |
| 幸存者偏差 | 只研究今天还存在的赢家，漏掉过去失败或退市者 |
| 过度拟合 | 模型记住历史偶然变化，离开原数据就失效 |
| 数据窥探 | 不断看同一结果并修改规则，直到碰巧漂亮 |
| 多重检验 | 试很多方案却只展示最好的一个，放大偶然中奖概率 |
| 滚动检验 | 每次只用当时已知数据训练，再向前测试一段 |
| 鲁棒性 | 参数、资产或时期稍变时，结论仍大致成立 |
| 复现 | 按论文或项目说明重新运行，检查是否得到相近结果 |

### 风险与评价

| 术语 | 通俗解释 |
|---|---|
| 波动率 | 收益上下变化的幅度，常用标准差估计 |
| 最大回撤 | 总资产从过去最高点跌到之后最低点的最大比例 |
| 夏普比率 | 平均超额收益除以收益波动，是比较指标，不是安全证明 |
| 尾部风险 | 很少发生但一旦发生损失很大的风险 |
| 在险价值 | 给定概率和期限下，模型认为通常不会超过的损失门槛 |
| 预期损失尾值 | 损失已经超过门槛以后，平均大约会亏多少 |
| 压力测试 | 假设极端市场情况发生，检查组合后果 |
| 情景分析 | 人为设定多个市场变量同时变化，检查组合后果 |
| 敏感性分析 | 改变一个假设或参数，观察结果变化多少 |
| 风险敞口 | 组合对某个价格、市场或因子实际暴露多少 |

### 论文、代码与平台

| 术语 | 通俗解释 |
|---|---|
| DOI | 论文的长期数字标识，格式通常像 `10.xxxx/xxxxx` |
| 预印本 | 正式同行评审前公开的论文版本，可能以后被修改 |
| 同行评审 | 同领域研究者在发表前检查方法和论证的过程 |
| 引用 | 后来的论文在参考文献中使用了这项研究；引用多不保证结论正确 |
| 仓库 | 保存代码、说明和修改历史的项目目录 |
| 提交 | 版本控制中记录的一次明确修改 |
| 分支 | 从同一代码历史分出的独立修改路线 |
| 许可证 | 规定代码或数据可以怎样使用、修改和分发的法律条款 |
| API | 程序按照约定格式向另一个系统请求数据或功能的接口 |
| API 密钥 | 数据服务发给用户或程序的一串秘密凭证，用来识别身份和计算用量；不能写进公开代码 |
| 依赖 | 一个程序运行时需要的其他软件库 |
| 环境 | Python 版本、依赖版本和系统配置的组合 |
| 自动测试 | 用预先规定的输入和答案自动检查程序行为 |
| 编程语言 | 人用来描述程序逻辑、计算机能够执行的一套语法和规则；Python、R、C++、C# 和 Rust 都是编程语言 |
| 云计算 | 使用服务商远程计算机运行程序或保存数据，而不是只使用自己的电脑 |
| 部署 | 把研究代码整理成能够按计划持续运行、监控和更新的系统 |
| 优化 | 在一组限制条件下寻找目标值最好的一种方案，例如在风险限制下寻找组合权重 |
| 约束 | 优化或交易必须遵守的限制，例如单只股票权重不能超过 `5%` |
| 聚类 | 根据相似程度自动把对象分组的方法 |
| 金融计量 | 把统计方法用于金融价格、收益和风险数据的研究领域 |
| 随机过程 | 数值随时间随机变化的数学模型；随机微积分是研究这种连续变化的高级数学工具 |

## 6. 看到漂亮收益时立即问

1. 信号和成交是否错用了同一天价格？
2. 数据里是否只有今天仍存在的资产？
3. 作者总共试了多少种规则，却只展示了几个？
4. 手续费、价差、滑点、冲击和融资成本是否齐全？
5. 参数稍微变化后结果是否消失？
6. 最终测试集是否真的只看了一次？
7. 结果是否只来自少数几天或少数资产？
8. 基准是否公平，风险是否相近？
9. 极端亏损时能否真实成交和继续融资？
10. 这个结果为什么在竞争市场中仍可能存在？

任何一项答不清楚，都表示“还需要研究”，不表示“策略已经成立”。
